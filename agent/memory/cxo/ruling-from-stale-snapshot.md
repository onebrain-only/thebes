Before refusing a mechanism, read the mechanism **in the working tree**, not at the last commit and
never from my own earlier ruling. A ruling says what should be; only the tree says what is.

**Why:** it happened twice on 2026-09-18. `D-052`(a) — I reasoned from `D-033` to what the corpus
must contain and ranked a defect first on an architecture that existed in `DECISIONS.md` and nowhere
else. `D-054` — I refused rail collapse because it "would need a second chevron affordance", while
the seat building it had already chosen selected-row-collapses with no second hit target. In the same
entry I had used that exact principle (`D-046`, no second tappable interaction) to forbid live
specimens in cards, then demanded the violation of it four parts later.

**How to apply:** when work is being built in parallel, `git status` the gallery/feature directory
before ruling on it — untracked files are the tell. Refuse a mechanism only after quoting the line
that implements it. A second leg of reasoning that sounds independent usually is not: in `D-054` the
corpus-size leg died on my own landing-page ruling, which had changed the rail's job underneath it.
